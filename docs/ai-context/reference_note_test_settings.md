# 参照メモ — pytest 初期体験改善の意図

## 背景
現状のテンプレートは、本番寄りの fail-closed な設定思想になっている。  
これは良いが、pytest 実行時にも通常の `config.settings` を使っている場合、ローカル初回実行時に `.env` 未整備で落ちやすい。

## 改善の本質
セキュリティを緩めるのではなく、以下のように責務分離すること。

- 本番設定: 厳しく保つ
- 開発設定: 開発しやすさを優先
- テスト設定: `.env` なしで動きやすくする

## 期待効果
1. clone → install → pytest の体験を良くする
2. テスト失敗原因の切り分けを簡単にする
3. CI とローカルの差を減らす
4. テンプレート再利用時の初動を軽くする

## 実装の基本方針
- `config/settings_test.py` を追加
- `pytest.ini` で `config.settings_test` を参照
- テスト用のダミー値を設定
- README に `.env` 不要でテスト可能なことを追記
- 本番設定の制約は崩さない

## やりすぎないこと
- billing や paywall の設計変更
- 不要な大規模リファクタリング
- 本番設定の緩和
